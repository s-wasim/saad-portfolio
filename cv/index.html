ch 02 · method{{ chIdx }}

METHOD

How a document becomes a row in a database. Five steps, the same five every time. Scroll: the diagram holds still and lights the part being described.

STEP 01 · SHAPE

Draw the state machine first

Before any prompt gets written, the whole job is a graph on paper: nodes, edges, what state each node reads and writes. If it can't be drawn, it isn't understood yet. LangGraph because the graph is the artifact — not a crew of agents improvising a plan at runtime.

STEP 02 · BUDGET

Count the model calls

Three LLM calls per document, capped, and the cap is a test. Vision for classification, structured output for extraction, and that's the budget. Every call that isn't in the budget is a cost you'll discover in production instead of in review.

STEP 03 · SCHEMA

Make the model return a shape

Structured output, schema-enforced, validated by code that has never heard of a language model. Cross-field logic is cheap and deterministic; use it. When validation fails, repair gets exactly one attempt — then it becomes a human's problem, on purpose.

STEP 04 · GATE

Put the human where it matters

Autonomy is not the goal — a correct write is. One approval gate, at the irreversible step, and the machine genuinely stops there. The amber indicator on this console is the same signal: hardware waits with the pipeline.

STEP 05 · SHIP

Hand over something that runs

Dockerfile, pytest suite, README that assumes nothing. 69 tests green on document_pipeline. The deliverable is a service your team can deploy and modify without me — not a notebook I have to be present to explain.
